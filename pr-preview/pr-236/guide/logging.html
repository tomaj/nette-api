Logging ​

When the DI container has a service implementing Tomaj\NetteApi\Logger\ApiLoggerInterface, ApiPresenter calls it after the handler ran.

Logs are masked by default since 4.0.0

The presenter replaces secret header values and secret query parameter values with *** before they reach log(). See Masking. In 3.x the logger got the headers exactly as they arrived, unless you called setMaskedLogHeaders().

The interface ​

php
public function log(
    int $responseCode,
    string $requestMethod,
    string $requestHeader,
    string $requestUri,
    string $requestIp,
    string $requestAgent,
    int $responseTime
): bool;
ArgumentValue
$responseCodethe status code sent
$requestHeaderall request headers, one Name: value per line, masked
$requestUriREQUEST_URI, with the query string, masked
$requestIpfrom the IpDetectorInterface service, which must exist
$responseTimemilliseconds

Example ​

The logging example writes JSON lines:

php
<?php

declare(strict_types=1);

namespace App;

use Tomaj\NetteApi\Logger\ApiLoggerInterface;

/**
 * Writes one JSON line per API request.
 * The headers arrive as "Name: value" lines; secret header and query parameter values are already *** because the presenter masks them.
 */
final class FileApiLogger implements ApiLoggerInterface
{
    public function __construct(private string $file)
    {
    }

    public function log(
        int $responseCode,
        string $requestMethod,
        string $requestHeader,
        string $requestUri,
        string $requestIp,
        string $requestAgent,
        int $responseTime
    ): bool {
        $headers = [];
        foreach (explode(PHP_EOL, trim($requestHeader)) as $line) {
            [$name, $value] = array_map('trim', explode(':', $line, 2)) + [1 => ''];
            $headers[$name] = $value;
        }

        $line = json_encode([
            'code' => $responseCode,
            'method' => $requestMethod,
            'uri' => $requestUri,
            'ip' => $requestIp,
            'agent' => $requestAgent,
            'time_ms' => $responseTime,
            'headers' => $headers,
        ], JSON_UNESCAPED_SLASHES);

        return file_put_contents($this->file, $line . "\n", FILE_APPEND | LOCK_EX) !== false;
    }
}
yaml
services:
	- Tomaj\NetteApi\Misc\IpDetector
	- App\FileApiLogger(%appDir%/../log/api.log)

Masking ​

Since 4.0.0

Masking is on by default. 3.6.0 had only setMaskedLogHeaders(), off until you called it. See UPGRADE-4.0.md.

Before log() runs, the presenter replaces the value of every secret header and every secret query parameter. The name stays, so you still see what the client sent:

text
GET /api/v1/users?api_key=***&page=2
Authorization: ***
X-Request-Id: abc-123

What is masked by default ​

WhatDefaultConstant
headersAuthorization, Proxy-Authorization, Cookie, Set-Cookie, X-Api-KeyApiPresenter::DEFAULT_MASKED_LOG_HEADERS
header patterns*token*, *secret*, *key*, x-auth-*ApiPresenter::DEFAULT_MASKED_LOG_HEADER_PATTERNS
query parametersapi_key, apikey, key, token, access_token, refresh_token, id_token, auth, password, secret, signature, sig, code, client_secretApiPresenter::DEFAULT_MASKED_LOG_QUERY_PARAMS
authorization namesthe header of every HeaderApiKeyAuthentication, the parameter of every QueryApiKeyAuthentication, the cookie of every CookieApiKeyAuthenticationread from the registered endpoints
  • Names and patterns compare case-insensitively. In a pattern, * is any characters, so *token* masks X-Auth-Token and X-Refresh-Token, and x-auth-* masks X-Auth-User.
  • A query parameter also masks its array forms, token[]= and token[a]=.
  • The whole Cookie header is masked. When you remove Cookie from the list, only the cookies read by a CookieApiKeyAuthentication stay masked inside it: Cookie: lang=en; api_session=***.
  • The authorization names are added as long as that kind of masking is on. Turn the headers or the query parameters off and they go too.

Change the lists ​

Each list has a setter that replaces it, and an add and a remove for one entry. Call them in the setup: of the apiPresenter service:

yaml
services:
	apiPresenter:
		factory: Tomaj\NetteApi\Presenters\ApiPresenter
		setup:
			- addMaskedLogHeader(X-Session)
			- removeMaskedLogHeader(Set-Cookie)
			- addMaskedLogHeaderPattern(x-signature-*)
			- removeMaskedLogHeaderPattern('*key*')
			- addMaskedLogQueryParam(session_id)
			- removeMaskedLogQueryParam(code)

This is the one apiPresenter service from Getting started: add these setup: lines to it, or put the block in another config file under the same name and Nette merges the two. Do not register a second ApiPresenter service; two of them fail with "Multiple services of type Tomaj\NetteApi\Presenters\ApiPresenter found".

MethodEffect
setMaskedLogHeaders(array $headers = DEFAULT_MASKED_LOG_HEADERS)replaces the header names; without an argument it restores the defaults
setMaskedLogHeaders([])turns header masking off, with the patterns and the authorization headers and cookies
addMaskedLogHeader(string), removeMaskedLogHeader(string)one header name; an add turns header masking on again
setMaskedLogHeaderPatterns(array $patterns = DEFAULT_MASKED_LOG_HEADER_PATTERNS)replaces the patterns; [] keeps only the names
addMaskedLogHeaderPattern(string), removeMaskedLogHeaderPattern(string)one pattern
setMaskedLogQueryParams(array $params = DEFAULT_MASKED_LOG_QUERY_PARAMS)replaces the parameters; [] turns query masking off, with the authorization parameters
addMaskedLogQueryParam(string), removeMaskedLogQueryParam(string)one parameter
getMaskedLogHeaders(), getMaskedLogHeaderPatterns(), getMaskedLogQueryParams()the current lists, without the authorization names
setLogMasking(LogMaskMode|LogValueMaskerInterface), getLogMasking()how a value is masked, see Masking modes

A wrong entry fails at once with what is wrong and how to fix it:

text
removeMaskedLogHeader('Set-Cokie'): 'Set-Cokie' is not in the masked headers (Authorization, Proxy-Authorization, Cookie, Set-Cookie, X-Api-Key), so there is nothing to remove. Did you mean 'Set-Cookie'? Entries compare case-insensitively; fix the spelling or leave the entry out.
removeMaskedLogHeader('X-Auth-Token'): 'X-Auth-Token' is not in the masked headers (Authorization, Proxy-Authorization, Cookie, Set-Cookie, X-Api-Key), so there is nothing to remove. It is masked by the pattern '*token*'; remove the pattern, or replace the patterns with a narrower list.
addMaskedLogHeader('X-*'): it contains *, which is only for header patterns. Add it as a pattern, or write the full header name.
addMaskedLogQueryParam('token[]'): it is not a query parameter name. Write only the name without =, &, ?, # or brackets, for example api_key (it also masks api_key[] and api_key[x]).

With the DI extension the same is in the logging: section:

neon
api:
	logging:
		maskHeaders:
			add: [X-Session]
			remove: [Set-Cookie]
			patterns: {add: [x-signature-*], remove: ['*key*']}
		maskQueryParams:
			add: [session_id]
			remove: [code]
maskHeaders / maskQueryParamsEffect
true (default)the defaults
falsemasking off
a list, for example [Authorization, X-Session]replaces the default names; header patterns stay
{names: [...], add: [...], remove: [...]}names replaces the defaults, then add and remove change them
patterns: (only maskHeaders)true, false, a list, or {add: [...], remove: [...]}

Quote a pattern that starts with * in NEON, '*key*'.

Masking modes ​

ModeAuthorization: Bearer abcdefghijklmnop?api_key=abcUse
LogMaskMode::Full (default)Authorization: ***?api_key=***nothing of the secret in the log
LogMaskMode::PartialAuthorization: Bearer abcd***?api_key=***tell keys apart; values shorter than 12 characters become only ***, a known auth scheme such as Bearer or Basic is kept
LogMaskMode::HashAuthorization: hash:2e6ad69016f66d4b?api_key=hash:ba7816bf8f01cfeafind all requests with the same key without logging it
LogMaskMode::Omitthe header line is left outthe parameter is left outnothing about the secret, not even that it was sent
yaml
services:
	apiPresenter:
		factory: Tomaj\NetteApi\Presenters\ApiPresenter
		setup:
			- setLogMasking(Tomaj\NetteApi\Logger\LogMaskMode::Hash)
neon
api:
	logging:
		masking: hash          # full, partial, hash, omit, or your own masker
		hashKey: %env.API_LOG_HASH_KEY%

Hash is not encryption

hash: is the first 16 hex characters of SHA-256. A short or guessable key, a 6-digit PIN or a word, can be found by hashing every candidate. Set hashKey (or new LogValueMasker(LogMaskMode::Hash, $key)) to a long random secret kept out of the log, then the value is an HMAC-SHA-256 that cannot be checked without the key. The key works only with hash; with another mode it fails.

For anything else implement Tomaj\NetteApi\Logger\LogValueMaskerInterface. mask() gets the value (a query value URL-decoded) and returns the text to log, or null to leave the header or parameter out. A query value is URL-encoded again, so *** (3 chars) is logged as ***%20%283%20chars%29:

php
final class LengthMasker implements LogValueMaskerInterface
{
    public function mask(string $value): ?string
    {
        return '*** (' . strlen($value) . ' chars)';
    }
}
neon
api:
	logging:
		masking: App\Api\LengthMasker

Turn masking off ​

neon
api:
	logging:
		maskHeaders: false
		maskQueryParams: false

Without the DI extension call setMaskedLogHeaders([]) and setMaskedLogQueryParams([]).

What is not masked ​

  • The body: log() never gets the request or the response body.
  • The $requestAgent and $requestIp arguments.
  • The console and Tracy: the console shows the request you type, and Tracy's bar and bluescreen show the raw headers and $_GET. Keep Tracy in production mode, where the bluescreen is not shown, and mask its logs yourself if you need to.
  • Path segments: /api/v1/users/secret-id stays as it is. Do not put secrets in the path.

What is logged ​

ResponseLogged in 3.x
handler result, any codeyes
500 from an exception or a failed output checkyes
404 Unknown api endpointyes
400 wrong input, 401, 429, 500 from an exception in authorized()no, the presenter returns before the logger

FAQ ​

Why are my 401 responses missing from the log? ​

They return early in 3.x, see the table. Log them in your own error handler if you need them.

Do I need an IP detector for logging? ​

Yes, the presenter takes IpDetectorInterface from the container. Prefer one that reads only REMOTE_ADDR; see Authorization.

Where do exceptions go? ​

To Tracy, through Debugger::log() in DefaultErrorHandler. See Error handling.

Can I log the response body? ​

Not through this interface, it gets only the code. Wrap the handler or the error handler if you need more.

Does the return value of log() matter? ​

No, the presenter ignores it.

Do I keep the masking in my own logger? ​

Not for headers and query parameters, the presenter masks them. Keep it for anything else you log, such as path segments.

Why is my X-Request-Key header masked? ​

The *key* pattern matches it. Remove the pattern with removeMaskedLogHeaderPattern('*key*'), or replace the patterns with a narrower list.
