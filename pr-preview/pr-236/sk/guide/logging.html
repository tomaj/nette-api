Logovanie ​

Keď má DI kontajner službu implementujúcu Tomaj\NetteApi\Logger\ApiLoggerInterface, ApiPresenter ju zavolá po behu handlera.

Od verzie 4.0.0 sa logy predvolene maskujú

Presenter nahradí hodnoty tajných hlavičiek a tajných query parametrov reťazcom *** skôr, než sa dostanú do log(). Pozrite Maskovanie. V 3.x dostal logger hlavičky presne tak, ako prišli, ak ste nezavolali setMaskedLogHeaders().

Rozhranie ​

php
public function log(
    int $responseCode,
    string $requestMethod,
    string $requestHeader,
    string $requestUri,
    string $requestIp,
    string $requestAgent,
    int $responseTime
): bool;
ArgumentHodnota
$responseCodeodoslaný stavový kód
$requestHeadervšetky hlavičky požiadavky, jedna Name: value na riadok, zamaskované
$requestUriREQUEST_URI aj s query stringom, zamaskované
$requestIpzo služby IpDetectorInterface, ktorá musí existovať
$responseTimemilisekundy

Príklad ​

Príklad logovania zapisuje JSON riadky:

php
<?php

declare(strict_types=1);

namespace App;

use Tomaj\NetteApi\Logger\ApiLoggerInterface;

/**
 * Writes one JSON line per API request.
 * The headers arrive as "Name: value" lines; secret header and query parameter values are already *** because the presenter masks them.
 */
final class FileApiLogger implements ApiLoggerInterface
{
    public function __construct(private string $file)
    {
    }

    public function log(
        int $responseCode,
        string $requestMethod,
        string $requestHeader,
        string $requestUri,
        string $requestIp,
        string $requestAgent,
        int $responseTime
    ): bool {
        $headers = [];
        foreach (explode(PHP_EOL, trim($requestHeader)) as $line) {
            [$name, $value] = array_map('trim', explode(':', $line, 2)) + [1 => ''];
            $headers[$name] = $value;
        }

        $line = json_encode([
            'code' => $responseCode,
            'method' => $requestMethod,
            'uri' => $requestUri,
            'ip' => $requestIp,
            'agent' => $requestAgent,
            'time_ms' => $responseTime,
            'headers' => $headers,
        ], JSON_UNESCAPED_SLASHES);

        return file_put_contents($this->file, $line . "\n", FILE_APPEND | LOCK_EX) !== false;
    }
}

Maskovanie ​

Od verzie 4.0.0

Maskovanie je predvolene zapnuté. Vo verzii 3.6.0 bolo len setMaskedLogHeaders(), vypnuté, kým ste ho nezavolali. Pozrite UPGRADE-4.0.md.

Pred zavolaním log() presenter nahradí hodnotu každej tajnej hlavičky a každého tajného query parametra. Názov ostane, takže stále vidíte, čo klient poslal:

text
GET /api/v1/users?api_key=***&page=2
Authorization: ***
X-Request-Id: abc-123

Čo sa predvolene maskuje ​

ČoPredvoleneKonštanta
hlavičkyAuthorization, Proxy-Authorization, Cookie, Set-Cookie, X-Api-KeyApiPresenter::DEFAULT_MASKED_LOG_HEADERS
vzory hlavičiek*token*, *secret*, *key*, x-auth-*ApiPresenter::DEFAULT_MASKED_LOG_HEADER_PATTERNS
query parametreapi_key, apikey, key, token, access_token, refresh_token, id_token, auth, password, secret, signature, sig, code, client_secretApiPresenter::DEFAULT_MASKED_LOG_QUERY_PARAMS
mená z autorizáciíhlavička každej HeaderApiKeyAuthentication, parameter každej QueryApiKeyAuthentication, cookie každej CookieApiKeyAuthenticationnačítané zo zaregistrovaných endpointov
  • Mená a vzory sa porovnávajú bez ohľadu na veľkosť písmen. Vo vzore je * ľubovoľné znaky, takže *token* zamaskuje X-Auth-Token aj X-Refresh-Token a x-auth-* zamaskuje X-Auth-User.
  • Query parameter zamaskuje aj svoje poľové tvary, token[]= a token[a]=.
  • Zamaskuje sa celá hlavička Cookie. Keď Cookie zo zoznamu odstránite, maskované v nej ostanú len cookies, ktoré číta CookieApiKeyAuthentication: Cookie: lang=en; api_session=***.
  • Mená z autorizácií sa pridávajú, kým je daný druh maskovania zapnutý. Vypnite hlavičky alebo query parametre a zmiznú aj ony.

Zmena zoznamov ​

Každý zoznam má setter, ktorý ho nahradí, a add a remove pre jednu položku. Volajte ich v setup: služby apiPresenter:

yaml
services:
	apiPresenter:
		factory: Tomaj\NetteApi\Presenters\ApiPresenter
		setup:
			- addMaskedLogHeader(X-Session)
			- removeMaskedLogHeader(Set-Cookie)
			- addMaskedLogHeaderPattern(x-signature-*)
			- removeMaskedLogHeaderPattern('*key*')
			- addMaskedLogQueryParam(session_id)
			- removeMaskedLogQueryParam(code)

Toto je jediná služba apiPresenter zo stránky Začíname: pridajte k nej tieto riadky setup:, alebo dajte blok pod rovnakým názvom do iného konfiguračného súboru a Nette ich zlúči. Druhú službu ApiPresenter neregistrujte; dve skončia chybou „Multiple services of type Tomaj\NetteApi\Presenters\ApiPresenter found“.

MetódaÚčinok
setMaskedLogHeaders(array $headers = DEFAULT_MASKED_LOG_HEADERS)nahradí mená hlavičiek; bez argumentu obnoví predvolené
setMaskedLogHeaders([])vypne maskovanie hlavičiek aj so vzormi a s hlavičkami a cookies z autorizácií
addMaskedLogHeader(string), removeMaskedLogHeader(string)jedno meno hlavičky; add maskovanie hlavičiek znova zapne
setMaskedLogHeaderPatterns(array $patterns = DEFAULT_MASKED_LOG_HEADER_PATTERNS)nahradí vzory; [] ponechá len mená
addMaskedLogHeaderPattern(string), removeMaskedLogHeaderPattern(string)jeden vzor
setMaskedLogQueryParams(array $params = DEFAULT_MASKED_LOG_QUERY_PARAMS)nahradí parametre; [] vypne maskovanie query aj s parametrami z autorizácií
addMaskedLogQueryParam(string), removeMaskedLogQueryParam(string)jeden parameter
getMaskedLogHeaders(), getMaskedLogHeaderPatterns(), getMaskedLogQueryParams()aktuálne zoznamy, bez mien z autorizácií
setLogMasking(LogMaskMode|LogValueMaskerInterface), getLogMasking()ako sa hodnota zamaskuje, pozrite Režimy maskovania

Chybná položka zlyhá hneď s tým, čo je zle a ako to opraviť:

text
removeMaskedLogHeader('Set-Cokie'): 'Set-Cokie' is not in the masked headers (Authorization, Proxy-Authorization, Cookie, Set-Cookie, X-Api-Key), so there is nothing to remove. Did you mean 'Set-Cookie'? Entries compare case-insensitively; fix the spelling or leave the entry out.
removeMaskedLogHeader('X-Auth-Token'): 'X-Auth-Token' is not in the masked headers (Authorization, Proxy-Authorization, Cookie, Set-Cookie, X-Api-Key), so there is nothing to remove. It is masked by the pattern '*token*'; remove the pattern, or replace the patterns with a narrower list.
addMaskedLogHeader('X-*'): it contains *, which is only for header patterns. Add it as a pattern, or write the full header name.
addMaskedLogQueryParam('token[]'): it is not a query parameter name. Write only the name without =, &, ?, # or brackets, for example api_key (it also masks api_key[] and api_key[x]).

S DI rozšírením je to isté v sekcii logging::

neon
api:
	logging:
		maskHeaders:
			add: [X-Session]
			remove: [Set-Cookie]
			patterns: {add: [x-signature-*], remove: ['*key*']}
		maskQueryParams:
			add: [session_id]
			remove: [code]
maskHeaders / maskQueryParamsÚčinok
true (predvolené)predvolené hodnoty
falsemaskovanie vypnuté
zoznam, napríklad [Authorization, X-Session]nahradí predvolené mená; vzory hlavičiek ostanú
{names: [...], add: [...], remove: [...]}names nahradí predvolené, potom ich add a remove zmenia
patterns: (len maskHeaders)true, false, zoznam alebo {add: [...], remove: [...]}

Vzor, ktorý začína *, dajte v NEON do úvodzoviek, '*key*'.

Režimy maskovania ​

RežimAuthorization: Bearer abcdefghijklmnop?api_key=abcPoužitie
LogMaskMode::Full (predvolený)Authorization: ***?api_key=***nič z tajomstva v logu
LogMaskMode::PartialAuthorization: Bearer abcd***?api_key=***rozlíšiť kľúče; hodnoty kratšie ako 12 znakov budú len ***, známa autentifikačná schéma ako Bearer či Basic ostane
LogMaskMode::HashAuthorization: hash:2e6ad69016f66d4b?api_key=hash:ba7816bf8f01cfeanájsť všetky požiadavky s rovnakým kľúčom bez jeho zalogovania
LogMaskMode::Omitriadok hlavičky sa vynecháparameter sa vynechánič o tajomstve, ani to, že bolo poslané
yaml
services:
	apiPresenter:
		factory: Tomaj\NetteApi\Presenters\ApiPresenter
		setup:
			- setLogMasking(Tomaj\NetteApi\Logger\LogMaskMode::Hash)
neon
api:
	logging:
		masking: hash          # full, partial, hash, omit alebo vlastný masker
		hashKey: %env.API_LOG_HASH_KEY%

Hash nie je šifrovanie

hash: je prvých 16 hex znakov SHA-256. Krátky alebo uhádnuteľný kľúč, 6-miestny PIN či slovo, sa dá nájsť zahašovaním všetkých kandidátov. Nastavte hashKey (alebo new LogValueMasker(LogMaskMode::Hash, $key)) na dlhé náhodné tajomstvo, ktoré nie je v logu; hodnota je potom HMAC-SHA-256, ktorý sa bez kľúča overiť nedá. Kľúč funguje len s hash; s iným režimom zlyhá.

Na čokoľvek iné implementujte Tomaj\NetteApi\Logger\LogValueMaskerInterface. mask() dostane hodnotu (query hodnotu URL-dekódovanú) a vráti text do logu, alebo null, aby sa hlavička či parameter vynechali. Query hodnota sa znova URL-zakóduje, takže *** (3 chars) sa zaloguje ako ***%20%283%20chars%29:

php
final class LengthMasker implements LogValueMaskerInterface
{
    public function mask(string $value): ?string
    {
        return '*** (' . strlen($value) . ' chars)';
    }
}
neon
api:
	logging:
		masking: App\Api\LengthMasker

Vypnutie maskovania ​

neon
api:
	logging:
		maskHeaders: false
		maskQueryParams: false

Bez DI rozšírenia zavolajte setMaskedLogHeaders([]) a setMaskedLogQueryParams([]).

Čo sa nemaskuje ​

  • Telo: log() nikdy nedostane telo požiadavky ani odpovede.
  • Argumenty $requestAgent a $requestIp.
  • Konzola a Tracy: konzola ukazuje požiadavku, ktorú zadáte, a lišta a bluescreen Tracy ukazujú surové hlavičky a $_GET. Tracy nechajte v produkčnom režime, kde sa bluescreen neukazuje, a ak treba, jej logy maskujte sami.
  • Segmenty cesty: /api/v1/users/secret-id ostane, ako je. Tajomstvá do cesty nedávajte.

Čo sa loguje ​

OdpoveďLoguje sa v 3.x
výsledok handlera, ľubovoľný kódáno
500 z výnimky alebo zlyhanej kontroly výstupuáno
404 Unknown api endpointáno
400 zlý vstup, 401, 429, 500 z výnimky v authorized()nie, presenter skončí pred loggerom

Časté otázky ​

Prečo v logu chýbajú moje odpovede 401? ​

V 3.x končia predčasne, pozrite tabuľku. Ak ich potrebujete, logujte ich vo vlastnom error handleri.

Potrebujem na logovanie detektor IP? ​

Áno, presenter berie IpDetectorInterface z kontajnera. Uprednostnite taký, ktorý číta len REMOTE_ADDR; pozrite si Autorizáciu.

Kam idú výnimky? ​

Do Tracy, cez Debugger::log() v DefaultErrorHandler. Pozrite si Spracovanie chýb.

Môžem logovať telo odpovede? ​

Cez toto rozhranie nie, dostane len kód. Ak potrebujete viac, obaľte handler alebo error handler.

Záleží na návratovej hodnote log()? ​

Nie, presenter ju ignoruje.

Mám maskovanie nechať aj vo vlastnom loggeri? ​

Pre hlavičky a query parametre nie, tie zamaskuje presenter. Nechajte ho pre všetko ostatné, čo logujete, napríklad segmenty cesty.

Prečo je moja hlavička X-Request-Key zamaskovaná? ​

Zodpovedá jej vzor *key*. Odstráňte ho cez removeMaskedLogHeaderPattern('*key*'), alebo vzory nahraďte užším zoznamom.
