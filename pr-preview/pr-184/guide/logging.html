Logging ​

When the DI container has a service implementing Tomaj\NetteApi\Logger\ApiLoggerInterface, ApiPresenter calls it after the handler ran.

Mask secret headers

By default the logger gets the request headers exactly as they arrived, including Authorization, cookies and API keys. Since 3.6.0, call setMaskedLogHeaders() on the presenter. In 3.5.0, mask them in your logger.

The interface ​

php
public function log(
    int $responseCode,
    string $requestMethod,
    string $requestHeader,
    string $requestUri,
    string $requestIp,
    string $requestAgent,
    int $responseTime
): bool;
ArgumentValue
$responseCodethe status code sent
$requestHeaderall request headers, one Name: value per line
$requestUriREQUEST_URI, with the query string
$requestIpfrom the IpDetectorInterface service, which must exist
$responseTimemilliseconds

Example ​

The logging example writes JSON lines:

php
<?php

declare(strict_types=1);

namespace App;

use Tomaj\NetteApi\Logger\ApiLoggerInterface;

/**
 * Writes one JSON line per API request.
 * The headers arrive as "Name: value" lines; secret values are already *** thanks to setMaskedLogHeaders().
 */
final class FileApiLogger implements ApiLoggerInterface
{
    public function __construct(private string $file)
    {
    }

    public function log(
        int $responseCode,
        string $requestMethod,
        string $requestHeader,
        string $requestUri,
        string $requestIp,
        string $requestAgent,
        int $responseTime
    ): bool {
        $headers = [];
        foreach (explode(PHP_EOL, trim($requestHeader)) as $line) {
            [$name, $value] = array_map('trim', explode(':', $line, 2)) + [1 => ''];
            $headers[$name] = $value;
        }

        $line = json_encode([
            'code' => $responseCode,
            'method' => $requestMethod,
            'uri' => $requestUri,
            'ip' => $requestIp,
            'agent' => $requestAgent,
            'time_ms' => $responseTime,
            'headers' => $headers,
        ], JSON_UNESCAPED_SLASHES);

        return file_put_contents($this->file, $line . "\n", FILE_APPEND | LOCK_EX) !== false;
    }
}
yaml
services:
    - Tomaj\NetteApi\Misc\IpDetector
    - App\FileApiLogger(%appDir%/../log/api.log)

Masking headers ​

Since 3.6.0

ApiPresenter::setMaskedLogHeaders() replaces the values of chosen request headers with *** before they reach log(). It is off until you call it, so 3.x logging does not change by itself.

yaml
services:
    -
        factory: Tomaj\NetteApi\Presenters\ApiPresenter
        setup:
            - setMaskedLogHeaders()
CallMasked headers
setMaskedLogHeaders()Authorization, Proxy-Authorization, Cookie, Set-Cookie, X-Api-Key (ApiPresenter::DEFAULT_MASKED_LOG_HEADERS)
setMaskedLogHeaders(['X-Session', 'Authorization'])only the listed ones, the list replaces the default
setMaskedLogHeaders([])none

Names compare case-insensitively, so x-api-key matches X-Api-Key. The header stays in the log with its name, only the value becomes ***:

text
Authorization: ***
X-Trace: abc-123

Only headers are masked. A token in the query string, such as ?api_key= for QueryApiKeyAuthentication, stays in $requestUri; strip it in your logger.

What is logged ​

ResponseLogged in 3.x
handler result, any codeyes
500 from an exception or a failed output checkyes
404 Unknown api endpointyes
400 wrong input, 401, 429, 500 from an exception in authorized()no, the presenter returns before the logger

FAQ ​

Why are my 401 responses missing from the log? ​

They return early in 3.x, see the table. Log them in your own error handler if you need them.

Do I need an IP detector for logging? ​

Yes, the presenter takes IpDetectorInterface from the container. Prefer one that reads only REMOTE_ADDR; see Authorization.

Where do exceptions go? ​

To Tracy, through Debugger::log() in DefaultErrorHandler. See Error handling.

Can I log the response body? ​

Not through this interface, it gets only the code. Wrap the handler or the error handler if you need more.

Does the return value of log() matter? ​

No, the presenter ignores it.

Do I keep the masking in my own logger? ​

Not for headers once you call setMaskedLogHeaders(). Keep it for query string tokens, which the presenter does not touch.
