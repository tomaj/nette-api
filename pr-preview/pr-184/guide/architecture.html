Architecture ​

Every API request goes to one presenter, Tomaj\NetteApi\Presenters\ApiPresenter. It asks ApiDecider which endpoint matches, runs the checks in a fixed order and returns what the handler or the error handler produced.

The parts ​

PartClass or interfaceJob
PresenterApiPresenterRuns every step below. It is final.
Endpoint listApiDecideraddApi() registers endpoints, getApi() finds the one for a request.
EndpointEndpointIdentifierMethod, version, package and optional action.
HandlerApiHandlerInterface, usually BaseHandlerDeclares params and outputs, does the work.
AuthorizationApiAuthorizationInterfaceSays whether the request may run.
Rate limitRateLimitInterfaceOptional, per endpoint.
ErrorsErrorHandlerInterface, DefaultErrorHandlerTurns failures into JSON responses.
Output checksConfiguratorInterfaceDecides whether outputs are validated and error details shown.
LoggerApiLoggerInterfaceOptional, found in the DI container.

The order of the steps ​

  1. CORS headers are added to the response first, see CORS.
  2. Endpoint lookup. ApiDecider::getApi() compares the HTTP method, version, package and apiAction route parameters. No match means the built-in DefaultHandler, which answers 404 Unknown api endpoint.
  3. Rate limit. If the endpoint has one and it reports remaining 0, the answer is 429. See Rate limiting.
  4. Params are read. Every param from params() is read and validated, but errors are not reported yet.
  5. Authorization. authorized() false means 401, an exception from it means 500. See Authorization.
  6. Param errors now answer 400. Authorization runs first so that it can use the values (see the 3.4.2 changelog).
  7. The handler gets the values: handle(array $params). An exception goes to the error handler and becomes 500.
  8. Output check. When the configurator says so, the response must match one of outputs(), otherwise 500. See Outputs.
  9. Logging. If an ApiLoggerInterface service exists, the request is logged. See Logging.

Not every response is logged

Steps 3, 5 and 6 return early, so 429, 401, 400 and the 500 of a failing authorization never reach the logger in 3.x. 404, handler responses and handler or output errors are logged.

FAQ ​

Can I replace ApiPresenter with my own presenter? ​

Not by extending it, the class is final. You can configure it (setCorsHeader()) and swap its dependencies: the error handler, the configurator and the logger. See Error handling.

Why does a request with a wrong token and wrong params answer 401, not 400? ​

Authorization runs before param errors are reported. See step 6 above and Authorization.

Is the handler created for every endpoint on every request? ​

No. When you pass a class name to addApi(), the handler is taken from the DI container only when its endpoint is called. See Handlers.

What does the response of an unknown endpoint look like? ​

404 with {"status":"error","message":"Unknown api endpoint"}. The hello world example tests it.

Where do I see all the classes in one list? ​

In the Reference.
